# Power BI view

`powerbi/TariffComparison.pbip` is a Power BI Project: the report and semantic model stored as text files (PBIR report, TMDL model) so they can be versioned and reviewed in Git. It loads the tidy CSVs in `powerbi/data/`, which are generated from the same calculator and tariff data as the rest of this repository.

> **Status:** these files were generated by `scripts/build_powerbi_project.py` and checked by `tests/test_powerbi.py`. Every JSON file validates against Microsoft's published schemas, and the model's tables, relationships, DAX references and visual bindings are cross-checked. They have **not** been opened in Power BI Desktop, which only runs on Windows. If Desktop rejects any file, use the manual steps at the end; they rebuild the same view in about 15 minutes.

## No Windows? Use the HTML preview
`powerbi/preview.html` mirrors this report (same CSVs, pages, slicers, visuals and measure logic) and opens in any browser, including on a Mac: download the file and double-click it. It is an HTML page that follows the Power BI layout, not a Power BI rendering. Regenerate it with `python3 scripts/build_powerbi_preview.py`.

## Open it
1. Use a recent Power BI Desktop (Windows). If it doesn't offer to open `.pbip` files, turn on **File > Options and settings > Options > Preview features**: *Power BI Project (.pbip) save option*, *Store semantic model using TMDL format* and *Store reports using enhanced metadata format (PBIR)*, then restart.
2. Clone or download this repository and open `powerbi/TariffComparison.pbip`.
3. **Refresh.** By default the model reads the CSVs from this repository on GitHub (`DataLocation` parameter). To use local files instead, go to **Transform data > Edit parameters** and set `DataLocation` to the full path of `powerbi/data/` with a trailing backslash, e.g. `C:\repos\residential-rate-tariff-comparison\powerbi\data\`.
4. If Desktop asks about privacy levels for the GitHub source, choose *Public*.

## What's in it

**Page 1: Bill comparison**
- Slicers: monthly usage (0-3,000 kWh in 50 kWh steps; defaults to 1,000 kWh), billing month (blank = 12-month average, which matters for Duke's winter rates) and utility type (investor-owned or municipal).
- *Monthly bill at the selected usage*: bar chart, cheapest first.
- *What makes up the bill*: stacked bars by component (fixed charges, non-fuel energy, fuel, cost-recovery clauses).
- *Monthly bill by usage*: one line per utility from 0 to 3,000 kWh. Tier breaks at 1,000 kWh show as changes in slope.
- *Detail table*: bill, cents per kWh, difference from the lowest bill shown, fuel share and effective date.

**Page 2: Sources and validation**
- Each schedule's regulation type, effective date and primary source.
- The calculator's results next to independently published bills (Florida PSC and FMEA), including the Duke fuel discrepancy explained in `docs/VALIDATION.md`.

## Model

| Table | Rows | Source | Notes |
|---|---|---|---|
| Utilities | 8 | `utilities.csv` | one row per rate schedule |
| Bills | 5,856 | `bills.csv` | schedule x usage (61 levels) x month; total and component dollars |
| Components | 23,424 | `components.csv` | same bills in long form for stacked charts |
| Months | 12 | generated in Power Query | month name and season |
| Usage Level | 61 | generated in Power Query | disconnected table that drives the usage slicer |
| Validation | 9 | `validation.csv` | calculator vs. published bills |

Relationships: Bills, Components and Validation to Utilities on `tariff_key`; Bills and Components to Months on `month`. Usage Level is intentionally unrelated: measures read the slicer with `SELECTEDVALUE`, so the line chart can still show every usage level.

Measures (all in Bills except the component measure):

```dax
Monthly Bill = AVERAGE ( Bills[total_bill] )
Selected kWh = SELECTEDVALUE ( 'Usage Level'[kWh], 1000 )
Bill at Selected Usage =
    VAR k = [Selected kWh]
    RETURN CALCULATE ( [Monthly Bill], Bills[kwh] = k )
Cents per kWh at Selected Usage =
    VAR k = [Selected kWh]
    RETURN IF ( k > 0, DIVIDE ( [Bill at Selected Usage], k ) * 100 )
Lowest Bill at Selected Usage = MINX ( ALLSELECTED ( Utilities[utility] ), [Bill at Selected Usage] )
Difference vs Lowest =
    IF ( HASONEVALUE ( Utilities[utility] ), [Bill at Selected Usage] - [Lowest Bill at Selected Usage] )
Rank (1 = lowest) =
    IF ( HASONEVALUE ( Utilities[utility] ),
         RANKX ( ALLSELECTED ( Utilities[utility] ), [Bill at Selected Usage], , ASC, DENSE ) )
Fuel Share at Selected Usage =
    VAR k = [Selected kWh]
    RETURN DIVIDE ( CALCULATE ( AVERAGE ( Bills[fuel] ), Bills[kwh] = k ), [Bill at Selected Usage] )
Component at Selected Usage =          -- in Components
    VAR k = [Selected kWh]
    RETURN DIVIDE ( CALCULATE ( SUM ( Components[amount] ), Components[kwh] = k ),
                    CALCULATE ( DISTINCTCOUNT ( Components[month] ), Components[kwh] = k ) )
```

Colors come from a custom theme (`StaticResources/RegisteredResources/TariffTheme.json`) using the eight-color categorical palette validated for color-vision deficiency.

## What it does and does not show
Same limits as the calculator (`docs/METHODOLOGY.md`): bills are before gross receipts tax, franchise fees and local taxes; OUC assumes its lowest demand-level tier; rates are a snapshot as of 2026-11-04.

## Regenerate
```bash
python3 scripts/build_powerbi_data.py      # powerbi/data/*.csv
python3 scripts/build_powerbi_project.py   # powerbi/TariffComparison.*
python3 -m unittest tests.test_powerbi -v
```
Edits made in Power BI Desktop are saved back into these files. If you customize the report in Desktop, don't rerun `build_powerbi_project.py`, or it will overwrite your changes.

## Manual build (if Desktop won't open the project)
1. **Get data > Text/CSV**: load `utilities.csv`, `bills.csv`, `components.csv` and `validation.csv` from `powerbi/data/`.
2. **Enter data**: a `Months` table (month 1-12, month_name, season), and a `Usage Level` table with one column `kWh` (0, 50, ..., 3000). Or create Usage Level as a calculated table: `Usage Level = SELECTCOLUMNS ( GENERATESERIES ( 0, 3000, 50 ), "kWh", [Value] )`.
3. **Model view**: relate Bills, Components and Validation to Utilities on `tariff_key`, and Bills and Components to Months on `month`. Leave Usage Level unrelated. Sort `month_name` by `month`.
4. **New measure**: paste each measure above.
5. Build the visuals listed under *What's in it*, using `Utilities[short_name]` for categories and legends.
